# P4.3 — Separate platform delivery and state ownership

_Part of the [delivery roadmap](../ROADMAP.md)._

- [x] **Task 1.** After a working staging extraction, move platform configuration/delivery
      into a dedicated platform repository. Keep immutable service-specific
      application artifacts, narrow OIDC roles, previous-contract compatibility,
      and Phase 3 affected-workspace improvements.

      **Closed 2026-09-22 as a decision record, the same shape as P4.1 Task 1
      / P4.2 Task 1 (ADR-0025/ADR-0027): [ADR-0031](../decisions/0031-platform-delivery-repository-split.md)
      documents which four Terraform roots and workflow steps move to a new
      platform repository, which stay in this repository (Dockerfiles, image
      build/push, `ci.yml`/`security.yml`), the two-axis OIDC narrowing
      (per-repository build role plus per-environment/per-service deploy
      roles), and how the existing `staging-passed-<sha>` digest-promotion
      contract and P3.5 Task 5's affected-workspace scoping are preserved
      unchanged. Started ahead of a completed staging extraction, at the
      maintainer's explicit direction, per the same precedent P4.1 Task 1 and
      P4.2 Task 1 set — recorded explicitly per ADR-0031's Context section
      rather than silently skipped. No repository was created and no
      infrastructure, workflow, or IAM change was made; that is Task 3's job.
      Tasks 2-4 remain not started.**
- [x] **Task 2.** Inventory the four Terraform roots (`bootstrap`, `development`,
      `environment`, `production`), backend keys, locks, IAM trust, configuration,
      and owning workflows. Close #9/#10 before any ownership transfer.

      **Closed 2026-09-22.** Full per-root inventory (backend, locking, IAM/OIDC
      trust, configuration inputs, owning workflows) verified against source and
      recorded in [docs/OPERATIONS.md](../OPERATIONS.md)'s new "Platform delivery
      inventory (P4.3 Task 2)" section, including three corrections to
      ADR-0031's own "current state" summary (bootstrap has no S3 backend and no
      owning apply workflow at all; `platform.yml` runs a real `terraform plan`
      against staging only, not all four roots as the ADR's Context section
      implied; production's activation state has an out-of-Terraform SSM side
      channel the ADR never mentioned). Issues [#9](https://github.com/jessig1/vinylhound_new/issues/9)
      and [#10](https://github.com/jessig1/vinylhound_new/issues/10) remain open
      — #9 needs a real `terraform apply` against `bootstrap` with an AWS
      administrator identity, which no agent session can perform unilaterally;
      #10 is a workflow-hardening review this session did not attempt, since the
      roadmap ties both to gating Task 3's ownership transfer, not Task 2's own
      inventory. **Task 3 remains blocked on both issues being closed first.**
- [ ] **Task 3.** Rehearse development first: freeze the old writer, back up/version state,
      transfer configuration/workflow authority, verify an unchanged plan against
      the existing backend, then enable exactly one new writer. Transfer remaining
      roots individually with the same verification and rollback instructions.
      Do not recreate resources or create competing state authorities. Recover
      locks only with verified ownership and no active apply.
- [ ] **Task 4.** Demonstrate independent service delivery, scaling, health, migration,
      rollback, and activation/deactivation in staging. Keep production rehearsal
      gated on the unresolved Phase 2 issues.

Exit: evidence identifies one authorized writer per root, unchanged resource
